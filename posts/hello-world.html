第一篇：为什么用无构建静态站写博客

2026年11月23日 站点 静态站

这个博客没有构建步骤：没有 npm，没有 Ruby，没有模板引擎。仓库里就是几个 HTML 文件、一份 CSS、一份 JavaScript，以及一个 posts.json。推送到 main，GitHub Actions 把静态文件发到 Pages。

为什么这样选

博客真正的成本在「持续写」，不在「渲染」。一旦引入构建链，两年后想改一篇文章，就得先找回当时那个 Node 版本。静态站把这个问题直接抹掉：只要有浏览器和文本编辑器，就能维护。

一份清单，四个产物

文章的唯一事实源是 posts.json。首页列表、RSS、sitemap 都由它推导，避免「首页有、RSS 没有」这类脏数据。新增文章用一条命令：

python scripts/new_post.py --title "标题" --slug hello-world --summary "一句话摘要" --tags 随笔

脚本会生成文章页骨架，同步 posts.json、feed.xml 和 sitemap.xml，只用 Python 标准库。

本地怎么看效果

首页要用 fetch 读取 posts.json，浏览器不允许 file:// 这么做，所以本地预览需要起一个静态服务：

python -m http.server 8000

然后打开 http://localhost:8000。线上由 Pages 提供 HTTP 服务，没有这个问题。

取舍

  • 没有评论和搜索：需要时再按需接入，不默认背上第三方脚本。
  • 文章正文是 HTML：写起来比 Markdown 笨一点，但零依赖、首屏无闪白。
  • 清单手工/脚本维护：换来的是「打开就能看懂」的仓库结构。
能长期维护的方案，通常是最无聊的那个。
